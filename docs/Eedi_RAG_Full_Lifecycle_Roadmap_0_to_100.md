## 一、 项目背景与业务需求全景 (Project Requirements)

### 1.1 业务起源与核心出发点
* **输入资产**：教育辅导机构积累了一批真实的 1v1 师生在线辅导课程录音文字记录（Tutoring Transcripts），包含题目背景、学生答题、师生多轮问答对话。
* **现状与痛点**：这些非结构化的长篇口语记录属于“沉睡资产”，人工无法逐篇阅读分析，但里面沉淀了顶级的**学生真实困惑**和**名师独家教学经验**。
* **根本使命**：探索并验证：能否通过 AI / LLM / RAG 技术，把这些师生辅导文字稿盘活，转化为高价值的教学洞察与可交互的问答系统？
* **核心态度**：“从小做起、低成本验证（PoC）”，用一个低成本、极速跑通的原型证明其商业与教学价值，再决定是否进行更大投资。

---

### 1.2 系统必须回答的 10 个核心业务问题

系统必须能够清晰、有依据、带真实引用地回答以下两类共 10 个核心业务问题：

#### 维度 A：关于学生端（学情与错题洞察）
1. **高频困惑**：学生在辅导中最常提出的问题是什么？
2. **核心难点**：哪些概念、主题或题型是学生觉得最难理解、卡壳时间最长的？
3. **共性误区**：有哪些**认知错误（Misconceptions）**在不同学生身上反复出现？
4. **错题模式**：学生在做题/考试时最容易犯的错误类型是什么？
5. **困难学生画像**：那些多次重考或基础薄弱的学生，是否存在某种共性的思维卡点模式？

#### 维度 B：关于导师端（名师教学方法论与策略沉淀）
6. **核心解题套路**：经验丰富的金牌导师反复传授哪些通用的做题和思考策略？
7. **启发式教学技巧**：遇到极难懂的概念，导师用了哪些**通俗的比喻、分步引导（Scaffolding）**帮助学生豁然开朗？
8. **排除法与决策技巧**：当学生在两个高度相似的选项中纠结时，导师如何教他们做最终抉择？
9. **教研内容改进**：这些对话中有哪些信息可以直接用来优化现有的教材、微课、题库解析？
10. **未来 AI 应用机会**：基于这批真实对话数据，未来还能孵化出哪些有商业价值的 AI 产品形态？

### 1.3 功能范围与交付边界 (In-Scope vs Out-of-Scope)

| 边界类型 | 包含的功能与交付物 (In-Scope) | 明确不做的事情 (Out-of-Scope) |
| :--- | :--- | :--- |
| **数据处理** | 对多篇对话进行批量分析，自动提取考点、学生误区、导师引导步骤。 | 暂不做复杂的分布式大数据 ETL 集群，以单机高效脚本优先。 |
| **交互与问答** | 自然语言提问，系统从真实记录中检索证据，给出带**原始对话出处引用**的解答（拒绝凭空捏造）。 | 暂不开发海量并发的生产级大型 SaaS 多端应用。 |
| **界面原型** | 提供基于 Streamlit 的极简可交互双看板界面（宏观洞察 + 微观问答）。 | 暂不投入过高成本编写复杂的 React/Vue 商业定制前端。 |

---

### 1.4 对话型数据带来的三大特殊挑战

与一般的“图书/文档 RAG”不同，辅导对话数据有三个极为严苛的特殊要求：
1. **角色与意图分离**：对话中有“学生说错的话”和“导师正确的引导”，系统必须严格区分，**绝不能把学生的错误认知当成标准答案检索出来**。
2. **多轮上下文锚定**：单句对话（如“我知道了”、“选 B 对吗”）没有独立语义，必须将对话与**题目原文、学科考点、完整问答链**绑定在一起作为一个知识单元。
3. **严格的数据隐私**：辅导对话包含学生真实姓名等隐私，处理过程需保证数据安全和去标识化（De-identification）。

---

### 1.5 代理数据集 (Eedi Dataset) 映射定位

在没有客户实际专有私密数据前，采用知名在线教育平台 **Eedi 开源辅导对话数据集**（`Eedi/Question-Anchored-Tutoring-Dialogues-2k`）作为等价落地数据集：
* **结构对应**：
  - `dq-question-metadata.csv` ➔ 题目原题与选项（等价于考题库）
  - `dialogue-subjects.csv` ➔ 学科知识树（等价于课程考纲体系）
  - `anchored-dialogues/train.csv` ➔ 真实师生问答口语流（等价于辅导文字稿）

## 二、 阶段一：0 ➔ 1 构建并调优至真正可用的完整 RAG 核心系统

```
  [Step 1] 三表数据融合与清洗 ETL (data_fusion.py)
      │    - 关联 subjects + metadata + dialogues，合并回车碎句，去噪脱敏 ➔ cleaned_sessions.jsonl
      ▼
  [Step 2] LLM 教学知识结构化蒸馏抽取 (extract_knowledge.py)
      │    - Pydantic 强类型抽取：学生深层错因 (Misconceptions) + 导师启发策略 (Scaffolding)
      ▼
  [Step 3] 双引擎存储持久化 (storage_manager.py)
      │    - DuckDB 关系底表 (事实/时序/统计) + ChromaDB 双向量库 (错因库 + 策略库)
      ▼
  [Step 4] 意图分流检索与严格证据溯源链路 (rag_engine.py)
      │    - 宏观统计走 SQL；微观案例走向量语义检索；强制附带真实对话轮次引用
      ▼
  [Step 5] 全功能可交互双看板界面 (app.py)
      │    - Tab 1: 教学宏观洞察看板；Tab 2: 智能问答与对话高亮溯源抽屉
      ▼
  [Step 6] 基准测试集评测与深度调优 (evaluate_rag.py)
           - 针对 20 个真实业务 Query 进行检索相关度、抗幻觉率与回答质量闭环调优
```

### Step 1：三表关联融合与确定性清洗 ETL (`data_fusion.py`)
* **目标**：消除关系型数据碎片与孤岛，生成自包含的清洗后教学会话宽对象。
* **输入**：`dq-question-metadata.csv`、`dialogue-subjects.csv`、`train.csv`。
* **执行动作**：
  1. **学科知识树拼装**：将 Level 1 (Subject)、Level 2 (Topic)、Level 3 (Subtopic) 拼装为标准路径字符串。
  2. **题目元数据透视（Pivot）**：将分散多行的题干、LaTeX 数学公式与选项 A/B/C/D 组装为结构化字典。
  3. **说话人连续发言合并（Turn Compression）**：状态机合并相邻且 Speaker 相同的敲回车短句，重构时序。
  4. **去噪与 PII 脱敏**：正则清洗开场寒暄（`Hello, you OK?`）、尾部客套（`Thank you, take care`），屏蔽学生全名。
* **输出**：`data/cleaned_sessions.jsonl`。

---

### Step 2：LLM 教学知识结构化蒸馏抽取 (`extract_knowledge.py`)
* **目标**：将口语化多轮问答提炼为高密度的结构化教学资产，实现角色认知绝对隔离。
* **执行动作**：
  1. **Pydantic Schema 定义**：
     - `StudentMisconceptionProfile`：错误选项、深层错因名称、机理剖析、困惑触发词。
     - `TutorStrategyProfile`：教学法分类、破局提问原句（Aha moment prompt）、引导步骤链、比喻案例、成效。
  2. **双视角防污染 Prompt 约束**：严格限定学生言论为“待诊断错误样本”，导师引导与答案为“黄金范式”。
  3. **并发与健壮性**：`asyncio.Semaphore(5)` 速率控制 + 3 次指数退避重试 + 结构化强校验。
* **输出**：`data/extracted_pius.jsonl`。

---

### Step 3：双引擎存储持久化 (`storage_manager.py`)
* **目标**：打破纯向量库的局限，构建“确定性关系底表 + 模糊语义向量库”协同存储体系。
* **执行动作**：
  1. **初始化 DuckDB 关系表**（单文件零运维 `tutoring_knowledge.duckdb`）：
     - `tutoring_sessions`（会话与原题事实表）
     - `session_dialogue_turns`（清洗后的明细对话表，供回溯高亮）
     - `misconception_chunks`（学生错因与考点表，支持 SQL `GROUP BY` 聚合）
     - `tutor_strategy_chunks`（导师策略与话术表）
  2. **构建 ChromaDB 双向量集合**（物理隔离）：
     - Collection A：`student_misconceptions`（面向学情分析检索）
     - Collection B：`tutor_strategies`（面向教学法与名师话术检索）
  3. **语义增强模板构建**：将结构化字段拼接为高语义密度的 Embedding Document 并批量入库。

---

### Step 4：意图分流检索与严格证据溯源链路 (`rag_engine.py`)
* **目标**：解决“大模型统计幻觉”与“编造案例”痛点，实现 100% 有据可查的 RAG 链路。
* **执行动作**：
  1. **Query 意图路由器（Intent Router）**：
     - *宏观统计类*（如“学生常犯的 Top 5 错误是什么？”）➔ 自动生成并执行 DuckDB SQL 查询。
     - *微观策略类*（如“导师如何启发纠结在两选项的学生？”）➔ 路由至 ChromaDB 向量语义检索。
  2. **严格防幻觉 Prompt（Strict Grounding）**：
     - 强制要求模型回答中的每一条策略必须带有 `[Session ID: XX, Turn: YY]` 标签。
     - 模型被严禁自行凭空创造未在 Context 中出现的辅导案例。
  3. **明细回查拼装**：根据召回的 `session_id` 自动去 DuckDB 查询原始上下文，准备前端证据链。

---

### Step 5：全功能可交互双看板界面 (`app.py`)
* **目标**：提供专业直观的 Web 操作交互，让业务专家与管理者清晰体验数据价值。
* **界面模块**：
  - **Tab 1: 教学宏观洞察看板 (Analytics Dashboard)**：
    - 学科考点错误频次分布柱状图（实时 SQL 聚合生成）；
    - 共性认知误区词云与严重程度分类；
    - 导师教学成效与策略转化漏斗。
  - **Tab 2: 交互式知识问答与证据溯源 (Grounded Q&A)**：
    - 自然语言提问交互；
    - 结构化建议卡片输出（考点、误区、推荐启发提问、分步引导步骤）；
    - **抽屉式原始对话查看器**：点击“查看原始辅导实录”，高亮展示对应会话的完整师生问答上下文。

---

### Step 6：基准测试集评测与深度调优 (`evaluate_rag.py`)
* **目标**：建立 20 个黄金业务测试用例（覆盖前述 10 个核心业务问题），闭环调优至高可用标准。
* **调优指标矩阵**：
  - **检索命中率 (Recall@3)** $\ge 90\%$
  - **抗幻觉/忠实度 (Faithfulness)** $\ge 95\%$
  - **证据引用准确率 (Citation Precision)** $100\%$

## 三、 阶段二：1 ➔ 100 企业级工业化、多租户运维与商业产品矩阵

---

### Module 1：多租户隔离与细粒度权限控制 (Multi-Tenant ACL)
* **租户隔离**：Payload 注入 `tenant_id` 与物理 Collection 隔离结合。
* **权限下推（Filtered Search）**：
  - 检索请求携带当前用户的 `user_id`、`role_ids`、`department_ids` 和 `security_level`；
  - 向量引擎在底层 HNSW 图遍历时直接执行布尔过滤下推（Single-Stage Filter），确保跨部门、跨层级知识绝对零泄露。

---

### Module 2：工业级摄取中台与多模态扩展
* **异构格式接入**：集成 `MinerU (Magic-PDF)` 解析双栏与 LaTeX 试卷；`python-docx` 提取批注教案；`VLM (Qwen2-VL / GPT-4o)` 解析板书错题截图。
* **指纹去重与幂等入库**：
  - 计算 Chunk 内容哈希 `SHA-256` 拦截完全重复文本；
  - 基于 `uuid5(doc_id, content_hash)` 生成全局唯一确定性 ID，重复跑批零脏数据；
  - 结合 `MinHash` 局部敏感哈希识别相似度 $> 95\%$ 的冗余讲义。
* **削峰填谷**：引入 Kafka/RabbitMQ 消息缓冲与异步批量 Embedding，配置死信队列（DLQ）与指数退避重试。

---

### Module 3：高阶混合检索工程 (Hybrid Search & Reranker)
* **双路召回**：Dense 稠密语义向量（捕捉意图） + Sparse 稀疏 BM25/SPLADE（精确匹配医学/数学专有名词与公式）。
* **倒数排名融合（RRF）**：$RRF\_Score = \sum \frac{1}{60 + rank_i}$ 融合多路得分。
* **Cross-Encoder 深度重排**：调用 `BGE-Reranker-Large` 对 Top-30 候选精细打分截取 Top-5。
* **动态滑窗补齐 (Sentence-Window)**：根据 `prev_chunk_id` / `next_chunk_id` 自动展开前后文，杜绝上下文断层。

---

### Module 4：零停机蓝绿双索引热更新机制 (Blue-Green Re-indexing)
* **业务痛点**：升级 Embedding 模型（如 1536 维切换到 1024 维）或调整切词规则时，千万级索引重建需要数小时，不能停机。
* **工程方案**：
  - 客户端通过逻辑别名 `Alias: knowledge_prod` 访问；
  - 后台离线全量构建 `Collection_Green`，跑通自动化回归评测用例；
  - 毫秒级原子切换 Alias 指向 `Green`；
  - 旧版 `Blue` 延迟 24 小时后软释放，实现**零停机、无抖动全量平滑迁移**。

---

### Module 5：自动化 CI/CD 评测与可观测性中台
* **RAG Triad 持续评测**：接入 `Ragas` 每日自动抽检真实用户 Query，计算上下文相关度、回答忠实度与切题度。
* **可观测性监控**：接入 `LangSmith` 监控端到端耗时瀑布图、P99 延迟与 Token 成本。
* **Bad Case 自动回流闭环**：用户点踩或评分 $< 0.85$ 的问答自动打标落库，生成检索调优工单。

---

### Module 6：私有化模型微调与成本压降
* **指令微调数据集构建**：利用闭源大模型从 5000+ 场辅导记录中蒸馏出标准的 `[错题上下文 -> 启发式引导策略]` 微调对。
* **开源模型 LoRA 微调**：针对 `Qwen2.5-7B-Instruct` 进行领域微调。
* **私有化高吞吐部署**：采用 `vLLM` 本地私有化部署，满足教育行业极严格的隐私合规，同时降低 85% 以上长期 API 成本。

## 四、 全生命周期核心卡点与避坑速查表 (Risk Matrix)

| 阶段 | 潜在卡点 / 致命陷阱 | 根因分析 | 资深工程师避坑方案 |
| :---: | :--- | :--- | :--- |
| **0 ➔ 1** | **暴力切块（Chunking）导致语义尽失** | 按固定 500 Token 切分，把一句话斩断在中间，上下文完全丢失。 | **废弃固定切块**，以“题干+选项+完整问答链”为**教学交互单元（PIU）**整体处理。 |
| **0 ➔ 1** | **学生错误言论污染标准答案** | 向量检索直接命中学生的错解，大模型当成真理输出给用户。 | **严格实行角色隔离抽取**：学生错因进`错题库`，名师引导进`策略库`。 |
| **0 ➔ 1** | **大模型产生数据统计幻觉** | 期望纯向量库回答“总共有多少个错误”这类宏观聚合问题。 | **引入 DuckDB 存表**：统计问题走 SQL `GROUP BY`（0 成本、100% 准），语义问题走向量库。 |
| **0 ➔ 1** | **大模型编造教学案例（Hallucination）** | 缺少严格证据约束，模型凭空生成看似合理的假案例。 | Prompt 强制加入**严格溯源约束**：每条结论必须附带 `[Session ID, Turn ID]` 原始引用。 |
| **1 ➔ 100** | **数据脱敏不彻底引发合规危机** | 口语聊天中包含真实姓名（如 Lina Chen）、联系方式。 | 在 ETL 阶段前置 **双重脱敏过滤（正则模式 + 专用 NER 实体识别）**。 |
| **1 ➔ 100** | **专有名词/公式检索漏检** | 用户提问词汇与口语原始词汇不一致。 | 升级为 **Hybrid Search（Dense Vector + BM25）+ BGE-Reranker**。 |
| **1 ➔ 100** | **AI 助教直接报答案变“抄作业”** | 提示词发散，模型缺乏对教学节奏的控制。 | 采用 **LangGraph 状态机工作流**，强制单轮只能输出一个启发性问题，控制引导节奏。 |
| **1 ➔ 100** | **闭源 API 随规模扩大成本失控** | 每天数万次师生对话全部调用昂贵商业模型。 | 实施 **知识蒸馏与私有化小模型微调 (LoRA / vLLM)**，实现高吞吐低成本。 |
